01 — Foundations

Palette, type, signal states

Colors are borrowed from rail signal lights, not decoration — amber means running, teal means clear, red means stopped. The same three colors carry meaning on every page.

Display / data — IBM Plex Mono

task-042 · Running

Every identifier, status, timestamp and path is set in mono — this is a CLI-native tool, and the UI should read like the terminal output it's standing in for.

Body — IBM Plex Sans

Prompts, descriptions, findings

Human-written content — the task prompt, the plan description, review findings — stays in a plain grotesk so it's never confused with system data.

07 — Component mapping

Where dioxuslabs/components did the work

Badge → StatusPill

The 6 task states map directly onto the Badge primitive's variant prop — color is data, not styling per-instance.

Accordion → Plan / Review / Receipts

Collapsible sections replace three always-expanded blocks, so an idle task's detail page is three lines tall instead of a wall of placeholders.

Switch → Pause / Resume

The log page's boolean toggle becomes the accessible Switch primitive instead of a text link, with the same built-in keyboard support.

Card → task cards, settings cards

One Card component, restyled per surface, replaces bespoke divs across Dashboard and Settings.

Toast → Save / cancel feedback

Settings' green/red confirmation banners and any future cancel confirmation share one Toast primitive and one color contract.

Accordion → commit rows

TaskDiff's commit list becomes accordion rows so the unified diff body — the expensive part to render and read — stays opt-in per commit.
